# 节点多IP裂变

把「域名类型」的节点，通过 DoH 解析成多个入口 IP，并把每个 IP 裂变成一个独立节点。一个脚本即可完成，无需像官方那样串联「解析 + 裂变」两个操作。

## 原理

Sub-Store 的脚本操作支持 `async`，因此可以在同一个 `operator` 里直接 `await ProxyUtils.doh`：

1. 遍历所有节点，跳过本身就是 IP 的节点；
2. 对域名节点发起 DoH 解析，按需注入 EDNS Client Subnet（ECS）；
3. 把解析出的每个 IP 复制成一个新节点（仅替换 `server` 与 `name`）。

官方方案拆成两步，是因为第一步用来替换内置的「域名解析」步骤、只负责把结果挂到 `server` 上；本脚本把两步合并，效果一致且更省事。

## 配置

所有可调项集中在脚本**顶部 `CONFIG` 对象**，改配置只看开头即可。其中只有 `edns` / `dohs` / `doh` / `seq` 支持在「脚本操作」参数里运行时覆盖（见下方「参数」），其余项需直接改 `CONFIG`：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `dohs` | 腾讯/阿里/Cloudflare/Google/Quad9 | DoH 服务器列表，多源轮询；失败自动换源 |
| `resolveRetries` | `3` | 单条解析最多尝试几个 DoH 源（换源重试上限） |
| `resolveBackoffAfter` | `2` | 连续失败达该次数后插入退避等待（0 = 关闭） |
| `resolveBackoffMs` | `800` | 退避基础毫秒，实际等待 = base × 已退避轮次（线性） |
| `type` | `A` | 记录类型：`A` 解析 IPv4，`AAAA` 解析 IPv6 |
| `edns` | 移动/电信/联通 | ECS 线路列表，`name` 用于命名，`ip` 为对应运营商/地区客户端 IP |
| `seq` | `false` | 命名是否带序号 |
| `keepOriginal` | `false` | 是否额外保留一条原始域名节点 |
| `resolveLimit` | `1` | 每批同时解析几个节点（1 = 逐个串行） |

## 参数

在「脚本操作」的参数中填写 **键 / 值**，可运行时覆盖以下 4 项（其余 `CONFIG` 项请直接改脚本顶部）：`edns` / `dohs` / `doh` / `seq`。

- 键 `edns`：JSON 数组，每个元素含 `name`（线路标签，用于命名）和 `ip`（ECS 客户端 IP）

```json
[{"name":"移动","ip":"111.47.229.151"},{"name":"电信","ip":"116.207.181.162"},{"name":"联通","ip":"119.36.124.169"}]
```

- 键 `dohs`：JSON 数组，DoH 服务器列表（优先），如 `["https://doh.pub/dns-query","https://dns.alidns.com/dns-query"]`
- 键 `doh`：单个 DoH 服务器地址（兼容旧写法，会转成单元素 `dohs`），如 `https://223.6.6.6/dns-query`
- 键 `seq`：命名是否带序号，默认关闭（`false`）

**默认值**：不填时，用 `CONFIG` 里的默认值。

## 节点命名

- 单线路：用全称，如 `移动 - 原名`
- **同 IP 合并**：同一个 IP 被多条线路解析出来时，合并成一个节点，前缀取各线路首字（去重）用 `/` 连接。例如移动、电信、联通都解析到 `1.2.3.4` → `移/电/联 - 原名`。
  - 前缀顺序按 `edns` 列表顺序（默认 移→电→联）。想要别的顺序就调整 `edns` 列表顺序。
- 开启 `seq` 后带序号：如 `移/电/联 1 - 原名`
- 无解析结果 / server 本身是 IP 的节点：原样保留

## 使用方法

1. 打开 Sub-Store → 订阅 → 添加「脚本操作」；
2. 将 `script.js` 内容整体粘贴到脚本框；
3. 按需修改顶部 `CONFIG` 或填写参数；
4. 保存并刷新订阅。

## 可选：保留原始域名节点

把 `CONFIG` 里的 `keepOriginal` 设为 `true`，即可在裂变节点之外额外保留一条原域名节点。

## 注意事项

- 只对**域名**节点裂变，`server` 本身是 IP 的节点原样保留。
- 无解析结果时保留原节点，不会丢节点。
- 解析用「多 DoH 源轮询 + 失败换源重试 + 连续失败线性退避」，缓解单源被限速；并已用 `scriptResourceCache` 按 `(域名 + 类型 + 线路)` 缓存解析结果（缓存 key 带版本号 `doh:v2:`，升级可整体作废旧缓存）。
- 解析做了并发限制（`resolveLimit`），避免一次性打爆 DoH 导致超时。
- 若以 `mode=link`（远程链接）方式引入本脚本，可在链接末尾加 `#noCache`，让 Sub-Store 每次都重新拉取脚本内容、不吃脚本下载缓存。
- 裂变会让节点数量成倍增长，注意控制订阅体积。
- EDNS Client Subnet 本质是声明「请求方所在网段」，用于拿到就近/同线路入口，请按实际需求填写。
